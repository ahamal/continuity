Building the engine

The first page said how we think the mind makes sense of the world. Here we go through the same steps again, and for each one we work out what it has to become before an engine can do it.

We need a world to try it in, and we start with the simplest one we can: a grid. There is one thing on it, and it can be moved up, down, left or right. The engine is told nothing about what the moves do.

A move on the grid works like a curtain. The thing goes in at one place, we pick a move, and it comes out at another. The engine sees where it was and where it ended up, and nothing in between.

Identity

On the first page we were the ones who identified the ball. For now we do the same for the engine: we hand it one thing, and we tell it how that thing is described. Identifying things on its own comes later.

The description is a set of facts. A fact is a name with a value, such as x = 4 or y = 4. The move being made is a fact too: action = right. So at any moment the engine knows a handful of facts: where the thing is, and which move is being made.

That is all it starts with. It is not told what any move does, where the grid ends, or where the walls are.

Continuity

The engine sees one move. The thing is at x = 4, y = 4, the move is right, and afterwards it is at x = 5, y = 4. As with the curtain, it takes this to be the same thing, and it forms an idea of what happened to it: x went up by one.

It keeps that idea as a row. A row says which facts were known, what followed, and how many times that has been seen:

KnownWhat followedSeen
action = rightdx = +1, dy = 01

Here dx and dy are how much x and y changed. This row is a continuity. It is what "the blue curtain turns it blue" looks like inside the engine. Each time the same thing follows again the count goes up, and the count is the strength of the assumption.

The row is the same whether the engine made the move itself or watched it being made. That is what will later let it learn a game by watching.

Hierarchy of assumptions

With the curtain, one look gave us assumptions at several levels: any object, any ball, a red ball. The engine gets its levels from how many facts a row keeps. From that same move it can write two rows:

KnownWhat followed
Generalaction = rightdx = +1, dy = 0
Specificaction = right, x = 4, y = 4dx = +1, dy = 0

A row with fewer facts covers more. The general row answers for every place on the grid, including places the thing has never been. The specific row answers for one place only.

To answer a question, the engine takes every row whose facts are all true at that moment, and follows the one with the most facts.

The gold ball has its match here. Suppose there is a wall, and the engine tries going right beside it. Nothing changes. It keeps "going right adds one to x", because that is still right almost everywhere. Beneath it, it writes what it just saw: going right from this place changes nothing. The next time it is at that place, the more specific row answers.

Curiosity

Curiosity was a missing assumption. In the engine it becomes a number, worked out from the rows, for each move it could make from where it is:

  • 1 when it has no row for the move at all.
  • One divided by the count once the move has been seen, so it falls each time.
  • 0 once the move has been seen five times, or once it has a row for this exact place.

While it explores, the engine makes the move it is most curious about. When nothing nearby is interesting, it moves at random until something is. It stops exploring when it is no longer curious about any move. The five is a number we chose.

Reasoning

With the curtains, we got a blue cube by putting assumptions in order. The engine does the same to reach a place. We give it a goal, such as x = 8, y = 2. It asks its rows where each move would take it from here, then where each move would take it from there, and carries on until one of those chains ends at the goal. That chain of moves is its plan.

Most of the places in a plan are ones it has never been to. It can still plan through them, because the general rows answer for them.

Then it follows the plan, and checks each move against what it expected. When a move turns out differently, it writes down what it saw, as with the wall above, and plans again from where it is.

What we build first

The first version of the engine keeps the hierarchy as small as it can be: two levels. For every move it sees, it writes the general row, with the move alone, and the specific row, with the move at that exact place. It writes nothing in between.

For now we hand it three things: the facts that describe the thing, how to measure a change between two moments, and how far apart two places are. Everything else it has to find.

That is enough to try the whole loop: explore out of curiosity, build rows, plan, and correct itself. The next page runs it on a line, a grid, and a grid with a wall.
